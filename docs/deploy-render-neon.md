# Игра через интернет: Render + Neon

Render запускает всю игру (страницу и Node.js / Socket.IO) на одном HTTPS-адресе. Neon хранит миры и героев в PostgreSQL. Компьютер разработчика после публикации не нужен.

## 1. База Neon

1. В [консоли Neon](https://console.neon.tech/) создайте отдельный проект `survival-adventure` на плане **Free**, регион AWS **Frankfurt** (`aws-eu-central-1`). Если проект уже создан, используйте его.
2. Нажмите **Connect**, выберите базу и роль владельца. Для приложения включите **Connection pooling**.
3. Сохраните строку подключения только в переменной `DATABASE_URL` в Render. Сохраните параметры `sslmode=require` и `channel_binding=require` из строки Neon.

Адрес базы с паролем является секретом: не добавляйте его в Git, код клиента, скриншоты и публичные сообщения. Локальные `.env` игнорируются Git; `.env.example` содержит только образец.

Схема `identities`, `worlds`, `world_backups` создаётся приложением при первом запуске. Формат снимков тот же, что в SQLite: остаются коды миров, личные ключи героев и все игровые данные.

## 2. Веб-сервер Render

Исходники и `render.yaml` должны быть отправлены в GitHub в выбранную ветку.

1. В [Render Dashboard](https://dashboard.render.com/) выберите **New → Blueprint**, подключите репозиторий игры и ветку с `render.yaml`.
2. Проверьте, что сервис `survival-adventure` использует **Free**, а платная база или диск не создаются. Blueprint содержит только веб-сервис; база уже находится в Neon.
3. Вставьте строку Neon в запрошенную секретную переменную `DATABASE_URL`.
4. Запустите развёртывание и дождитесь **Live**. Render выдаст постоянный адрес `https://<имя-сервиса>.onrender.com`.

Если создаёте Web Service вручную, используйте:

| Параметр | Значение |
| --- | --- |
| Runtime | Node |
| Region | Frankfurt |
| Instance type | Free |
| Build command | `npm ci --include=dev && npm run build` |
| Start command | `npm start` |
| Health check | `/api/health` |
| `NODE_VERSION` | `24` |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Секретная строка Neon с SSL |

`PORT` задаёт Render; код слушает его на `0.0.0.0`. WebSocket работает через тот же адрес и порт. Не включайте несколько экземпляров сервера: активная симуляция мира хранится в памяти одного процесса.

На Render без `DATABASE_URL` приложение намеренно не запускается. Это предотвращает незаметную запись мира на временный диск.

## 3. Существующие локальные миры

Для нового приключения перенос не нужен. Для сохранения прежнего прогресса:

1. До перехода на новый адрес скопируйте личный ключ героя через **Esc → Скопировать ключ героя**. Каждый игрок сохраняет собственный ключ.
2. Сохраните игру и остановите локальный сервер. Скопируйте папку `data/` как резервную копию.
3. Создайте локальный `.env` по `.env.example`. Добавьте `DATABASE_URL_UNPOOLED` с **прямой** строкой подключения Neon: в окне Connect отключите Connection pooling. Миграция использует прямое подключение. Также допустима прямая строка в `DATABASE_URL`.
4. Выполните из папки проекта:

   ```sh
   npm run db:migrate
   ```

   Другой исходный файл можно указать как аргумент:

   ```sh
   npm run db:migrate -- /absolute/path/village.sqlite
   ```

5. Удалите `DATABASE_URL` из локального `.env` или переименуйте файл, если хотите дальше запускать локальную SQLite. Не запускайте вторую игровую симуляцию с той же облачной базой параллельно Render.
6. На новом адресе игры нажмите **Восстановить героя**, вставьте личный ключ и откройте прежний мир. Друг входит со своим ключом и тем же кодом мира.

Перенос читает SQLite без изменений и записывает все миры, проверенные резервные снимки и идентификаторы в одной транзакции. Повторный запуск пропускает полностью одинаковые миры. Если в Neon уже есть другой прогресс с тем же ID или кодом, вся транзакция отменяется: облачные данные не перезаписываются. Переносите до начала игры на Render.

## 4. Проверка

1. Откройте `<адрес-игры>/api/health`: должны быть `ok: true` и `storage: "postgresql"`.
2. В разных браузерах или на двух компьютерах создайте мир и присоединитесь по коду. Проверьте движение, подбор добычи и сохранение.
3. Сохраните, выйдите обоими героями и перезапустите сервис через Render. Войдите снова: мир, инвентарь, задания и время должны восстановиться.

Локальные проверки:

```sh
npm test
npm run check
npm run build
```

`tests/postgres.test.js` пропускается без `TEST_DATABASE_URL`. Для проверки на тестовой PostgreSQL задайте её в окружении и запустите `npm test`. Тесты создают отдельные временные схемы и удаляют только их. Используйте отдельную тестовую базу.

## Бесплатные ограничения

Render Free засыпает после 15 минут без входящего трафика; следующий запуск занимает около минуты. Локальный диск при засыпании или перезапуске очищается, поэтому сохранения находятся в Neon. Neon Free имеет лимиты вычислений, хранения и трафика; после исчерпания лимитов доступ может быть приостановлен. Не настраивайте искусственные запросы для предотвращения сна: для небольшой игры пауза при отсутствии игроков предусмотрена.

Условия сервисов: [Render Free](https://render.com/docs/free), [WebSocket](https://render.com/docs/websocket), [Render Blueprint](https://render.com/docs/blueprint-spec), [Neon Free](https://neon.com/pricing).
